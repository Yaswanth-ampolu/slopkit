Auto Runner

One button. Walks the WebKit .text range in small chunks, one page load per chunk, and sends every chunk's findings to the sink.

Why chunks. A single 8 MB sweep is about 33,800 carrier reads in one page load, and the tab runs out of memory long before it finishes — which is exactly the failure you are hitting. Scanning 0.25 MB per run is about 1,060 reads, then the page reloads and memory starts clean. The gadget map is assembled from all the chunks afterwards.

Spray is the only field that matters for the "not enough free system memory" panel. Coverage is plain arithmetic: sourceCovered = fakeChars*2 <= carrierBytes, and this console measured fakeChars = 924176 — so 1.85 MB is the real requirement. The old default asked for 69 MB, 39x more than needed, and that over-allocation is what the console refused. It is unrelated to the scan size. Start at 7.6 MB. Do not raise it unless source-covered=false appears in the log. 16 MB and above cover the source too, but only provoke the dialog sooner.
